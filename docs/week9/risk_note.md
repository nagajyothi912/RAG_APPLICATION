Who wrote it: "Support Ops" - simulated by us for Week 9 in backend/mcp_servers/ticket_history (commit a592f55); unsigned, not reviewed outside the team, and it runs as a subprocess under the same OS user as the agent.
What it reaches: every ticket in its tickets.json - customer names, phone numbers, customer ids, orders, amounts paid, install status, escalation notes - with no per-ticket scoping; and, as our OS user, any file we can read, including backend/.env (Groq key, admin password).
What it logs: one line per call (UTC time, tool, ticket id, outcome) to stderr and backend/data/ticket_history_access.log - never the caller, because stdio carries no identity; no rotation or retention limit, and ticket ids link straight to customers.
Stolen token: the stdio build has no token at all (whoever can launch it reads everything), and --http mode has no auth, so anyone who reaches the port can enumerate TCK-0000..9999 and dump all customer PII; its tool text also flows into our model's context (a Week 8 prompt-injection channel).
Verdict: don't ship as-is - ship only on stdio or behind HTTP with a read-only, ticket-scoped token, with the caller written to the audit log, and with its outputs sanitised as untrusted input before they reach the model.
